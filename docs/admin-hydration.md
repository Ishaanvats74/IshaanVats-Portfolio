# Payload admin head hydration

Payload 3.91.0 renders an anonymous `<style>` with `@layer payload-default, payload;` at the start of its head. A browser-injected style inserted before it can be mistaken for this node during React hydration. The reported `body[unresolved]` text is not generated by this project's source.

`scripts/patch-payload-style.mjs` adds stable `href` and `precedence` properties to that one style in Payload's installed RootLayout. React then matches it as a stylesheet resource by identity rather than by its position among anonymous style elements. The layer declaration is unchanged. The patch does not remove injected styles, disable server rendering, or suppress hydration warnings.

The patch runs on installation and before development/build commands. It is idempotent and fails explicitly if an upstream update changes the expected code. Review it when upgrading Payload and remove it once upstream supplies an equivalent fix. No other vendor source is modified by the script.

The regression test first reproduces the error with the original anonymous style. It then renders the installed patched style, injects the reported CSS before hydration, and checks that React reuses the server button, reports no hydration recovery, preserves the unrelated style, and handles a click.

Reference: [React stylesheet resource semantics](https://react.dev/reference/react-dom/components/style).

## Media-picker session origins

A separate local configuration fix handles cookie authentication for server actions: Payload trusts explicit `localhost`, `127.0.0.1`, and IPv6 loopback aliases on the configured scheme/port only when `NEXT_PUBLIC_SERVER_URL` is itself local. Public deployments trust only the configured origin. This prevents the GET/POST session mismatch when opening the local admin at the loopback IP while its configured URL uses localhost. The existing authentication and media access rules remain enforced.

The Neon S3 adapter also requires its generated storage-key fields. Apply all checked-in migrations with `npm run db:migrate` after enabling storage, including `20261023_083809_neon_storage_fields`.
